# PRD - 校園訂餐系統

## 1. 專案概述

### 背景與動機
遇到中午或下課尖峰時段，校園周邊的餐廳常常大排長龍，學生因此浪費許多時間在等待點餐與取餐上。為了解決這個痛點，本案預計開發一個「校園訂餐系統」，幫助學生利用下課前或空堂時間提前線上訂餐，店家也能提前接收訂單準備，減少排隊擁擠，提升雙方的效率與體驗。

### 目標用戶
- **學生（消費者）**：希望節省排隊時間、快速取得餐點的大學生。
- **店家（供應商）**：校園附近希望提升接單效率、擴展學生客源的餐廳業者。

### 核心價值主張
- **對學生**：節省大把排隊等候的時間，上課不再因為買不到午餐而遲到。
- **對店家**：分流尖峰時段人潮，有條理地接收及處理訂單，提升營業總量。

## 2. 功能需求

以下列出系統的核心主要功能，以及個別的使用者故事（User Story）：

### 1. 使用者註冊與登入
- **使用者故事**：作為一名「學生」，我希望可以「透過 Email 註冊並登入系統」，以便「在平台上建立專屬的訂餐帳號並管理我的個人資訊」。
- **使用者故事**：作為一名「店家」，我希望可以「註冊為餐廳帳號」，以便「在平台上管理我的菜單與接收訂單」。

### 2. 瀏覽餐廳與菜單
- **使用者故事**：作為一名「學生」，我希望可以「瀏覽合作的店家列表並且點進去看菜單與價格」，以便「選擇我想吃的午餐」。

### 3. 購物車功能
- **使用者故事**：作為一名「學生」，我希望可以「將想吃的餐點加入購物車並調整數量」，以便「確認總金額後再一起結帳」。

### 4. 線上送出訂單
- **使用者故事**：作為一名「學生」，我希望可以「線上送出我的餐點訂單並指定預計取餐時間」，以便「店家能提早開始準備，讓我到店就能拿走」。
- **使用者故事**：作為一名「店家」，我希望可以「在後台看到所有學生送出的訂單」，以便「依據訂單內容依序製作餐點」。

### 5. 查詢訂單紀錄
- **使用者故事**：作為一名「學生」，我希望可以「在我的帳號中查詢過去與目前的訂單狀態（處理中/已完成）」，以便「掌握餐點準備進度與過去的消費紀錄」。

## 3. 非功能需求

### 技術限制
- 原則上使用 **Flask** 作為後端框架。
- 搭配 **Jinja2** 作為前端樣板引擎。
- 資料庫採用輕量級的 **SQLite**，適合快速開發與驗證 MVP。

### 效能與安全考量
- **響應速度**：系統載入頁面應在 2 秒內完成，確保學生滑手機點餐的流暢度。
- **安全性**：使用雜湊演算法（如 bcrypt 或 werkzeug.security）妥善加密儲存使用者密碼。
- **RWD（響應式設計）**：由於大學生主要透過手機點餐，介面必須適配手機版螢幕（Mobile-first）。

## 4. MVP 範圍 (Minimum Viable Product)

| 優先級數 | 涵蓋功能 (Features) |
| --- | --- |
| **Must Have** (核心必備) | 1. 學生/店家基本註冊與登入<br>2. 學生可瀏覽店家與菜單<br>3. 學生購物車與送出訂單<br>4. 學生能查詢訂單狀態<br>5. 店家能看到學生訂單 |
| **Should Have** (重要需求) | 1. 店家可以自己新增/修改菜單<br>2. 訂單狀態更新通知 (如：店家標記「已出餐」)<br>3. 基本數據儀表板 (如：店家今日營業額) |
| **Nice to Have** (未來擴充) | 1. 線上金流支付整合 (目前初期可先採取到店付費)<br>2. 評價與評分系統<br>3. 揪團訂餐功能 |
