# Product Requirements Document (PRD) - 任務管理系統

## 1. 專案概述
- **背景與動機**：現代人生活忙碌，常常因為缺乏有效的紀錄方式而遺忘重要事項。為了解決這個問題，我們需要一個簡單、直覺的任務管理工具來協助記錄並追蹤待辦事項。
- **目標用戶**：需要管理日常任務、工作待辦清單或個人計畫的一般大眾。
- **核心價值主張**：提供一個輕量、簡單但能有效集中管理任務的平台，減少因為忘記待辦事項所帶來的焦慮與困擾，提高生活與工作效率。

## 2. 功能需求
1. **新增任務 (Create Task)**
   - 作為 **使用者**，我希望 **能夠輕易地新增一筆待辦任務（填寫任務名稱等）**，以便 **記錄我接下來要做的事情**。
2. **瀏覽任務清單 (Read Tasks)**
   - 作為 **使用者**，我希望 **能夠一眼看到目前所有的任務列表**，以便 **清楚掌握我目前的任務與處理進度**。
3. **標記完成任務 (Complete Task / Update status)**
   - 作為 **使用者**，我希望 **能夠將已做完的任務標記為「完成」**，以便 **確認進度並獲得成就感**。
4. **刪除任務 (Delete Task)**
   - 作為 **使用者**，我希望 **能夠刪除不再需要或輸入錯誤的任務**，以便 **保持任務列表的乾淨與整齊**。
5. **編輯任務內容 (Edit Task) (可選)**
   - 作為 **使用者**，我希望 **能夠隨時修改現有任務的內容**，以便 **在任務內容改變時可以及時修正**。

## 3. 非功能需求
- **技術限制**：
  - 後端：遵循開發規範，使用 Flask (Python Web Framework)。
  - 前端：使用 Jinja2 模板引擎進行畫面渲染。
  - 資料庫：採用 SQLite 作為輕量級的資料存儲方案。
- **效能考量**：
  - 任務列表與各項操作（新增/完成/刪除）的回應時間應小於 1 秒，確保操作流暢。
- **安全考量**：
  - 必須防範 SQL Injection (透過參數化查詢或 ORM 完成)。
  - 必須防範 XSS (Cross-Site Scripting)，確保使用者輸入在頁面上顯示時能有適當的 HTML 跳脫 (利用 Jinja2 預設的 autoescape)。

## 4. MVP 範圍
- **Must Have (必須擁有)**
  - 瀏覽任務列表頁面
  - 新增單個任務的功能
  - 能切換任務的狀態 (如：待辦 -> 完成)
  - 刪除指定的任務
- **Should Have (應該擁有)**
  - UI 重視任務狀態區分 (在畫面上能夠明確辨識任務是否已完成)
- **Nice to Have (可以考慮擁有)**
  - 任務的分類過濾器 (如：全部、未完成、已完成)
  - 任務詳情的編輯功能
